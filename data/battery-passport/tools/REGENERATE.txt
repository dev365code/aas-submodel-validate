Regenerating the indexes
========================

Run from the directory that holds requirements-*.json, with the source files in
a sibling directory named sources/ laid out as sources.sha256 names them.

Step 0 -- fetch and verify the sources. Every line of sources.sha256 gives the
address the same bytes can be fetched from; the files are not redistributed
here. Then:

    cd sources && grep -v '^#' ../sources.sha256 | shasum -a 256 -c
    # expect: 25 lines, all OK

Step 1 -- five commands, in any order:

    python3 tools/extract_annex_xiii.py \
        --html sources/eurlex/02023R1542-20250731_EN.html \
        --out requirements-annex-xiii.json

    python3 tools/extract_ec_datapoints.py \
        --pdf "sources/ec-dg-grow/digital-batteries-passport-data-point-by-category_v2.0.pdf" \
        --out requirements-ec-datapoints.json

    python3 tools/extract_longlist.py \
        --xlsx "sources/batterypass/2026_BatteryPass-Ready_DataAttributeLongList_v1.3.xlsx" \
        --out requirements-longlist.json --public

    python3 tools/extract_idta_smt.py \
        --sources-dir sources/idta \
        --out requirements-idta.json

    python3 tools/join_requirements.py \
        --dir . --out requirements-join.json --md requirements-join.md

Step 2 -- the expected result is no change:

    git diff --exit-code -- requirements-annex-xiii.json \
        requirements-ec-datapoints.json requirements-longlist.json \
        requirements-idta.json requirements-join.json requirements-join.md
    # exit 0 means the indexes regenerated byte for byte

A non-empty diff means one of three things, in this order of likelihood: a
source moved and the hash check above was skipped; the tools were changed; or
the environment differs in a way the tools should not be sensitive to and are.
The third is a bug worth reporting.

Requirements: Python 3.9 or newer, openpyxl (spreadsheet), PyMuPDF (the guidance
table is read from the ruling lines the page draws, not from its text stream).

sources.sha256 is a static pin and is not regenerated here.

--public on the longlist extractor selects the redistribution profile. That
profile currently omits nothing: PUBLIC_PROFILE_OMITS in the script is empty, and
the script states the rule that keeps it so (a value the spreadsheet prints in its
own columns is the spreadsheet's). The flag stays so that wording lifted from a
document under other terms could be left out without changing the parse. The file
above is reproducible exactly as published.
