# Divergences and chosen readings

Every place this project had to choose a reading of IDTA 02004, IDTA
02003, IDTA 02035-2, or of the official material, with the evidence. Non-empty on day one: the official
template (2.0.1) and the official example disagree with each other in
the ways recorded below, so a validator has to decide whom to believe
before it can report anything.

| # | observation (verified against the published files, or against the requirements indexes in `data/battery-passport/` where a row says so) | our reading |
|---|---|---|
| 1 | The official example's `Entities` list carries idShort `Entites` (sic). | idShort is not a matching key (Annex A: "A different idShort might be chosen"), so a typo there is not a finding. Matching is by semanticId throughout. |
| 2 | The example's Entities list uses semanticId `…/EntityForDocumentation` (the *child* element's singular IRI) where the template says `…/EntitiesForDocumentation`. | Reported as a template-conformance finding with a nearest-miss diagnosis, not silently matched. |
| 3 | The template's language list is idShort `Language`; the example says `Languages`. | Harmless under semanticId matching; recorded so nobody "fixes" matching to depend on names. |
| 4 | Only `OrganizationShortName`'s main semanticId is an ECLASS-CDP URL (`https://api.eclass-cdp.com/0173-1-02-ABI002-003`) where every sibling uses an IRDI — in the template *and* the PDF alike. | semanticId comparison normalises CDP URLs to IRDIs, both directions; an instance carrying either spelling matches. |
| 5 | The template's `AllowedIdShort` qualifier values are written like `RefersTo[\d{2,3}]` — as a regular expression this is a character class and matches "RefersTo" plus one character. | We implement the evident intent, `^RefersTo(?:\d{2,3})?$` — the digits are the multiple-instance suffix and so optional, which is why the template's own single `PreviewFile` passes. Always an informational lint (HDL1). |
| 6 | The official template 2.0.1 itself fails aas-core3.0 metamodel verification — four errors across three conceptDescriptions: `ClassificationSystem` (0173-1#02-ABH997#003) carries both a duplicate-language `displayName` and a duplicate-language `definition`; `DocumentVersion` carries the duplicate `definition` alone; `PreviewFile` (0173-1#02-ABK127#002) the duplicate `displayName` alone. | The `meta` channel reports what the verifier finds, on official material as on anyone's. |
| 7 | The short name `RefersTo` appears in the PDF's §2.2 prose; all three short names (`RefersTo` / `BasedOn` / `TranslationOf`) appear in the template's `AllowedIdShort` qualifiers. The PDF's *tables* and the template's SML idShorts use the longer `RefersToEntities` / `BasedOnReferences` / `TranslationOfEntities`. | Harmless under semanticId matching; recorded so the short forms are not mistaken for element identities. |
| 8 | The template writes a list item's identity as two ECLASS ids joined by "/" inside one key (`0173-1#02-ABI500#003/0173-1#01-AHF579#003`), plus `~0`-suffixed and CDP-URL supplemental spellings. | A row matches on the union of the whole composite, its `~N`-stripped form, and the CDP-normalised form — **not** its "/"-split components. An earlier reading split composites into components ("the PDF cites the item id alone"); checked against the PDF that claim is false (the tables carry the composite), and the splitting let a Document collection's id match its parent Documents-list row. Composites are kept whole. |
| 9 | §2.3 says the mandatory classification is "identified by the value 'VDI 2770 Blatt 1:2020'" — but the template's own ExampleValue, and therefore the official example, write `VDI2770:2020`. | Both spellings count as the mandatory system (HD-D2..D4 apply to either); the non-canonical spelling draws HDL5, a warning that names §2.3's string. Failing the official example on the template's own example spelling would be dogma; matching only the example spelling would betray the specification's sentence. |
| 10 | The official example addresses list children by index in ModelReferences ("Documents / 0 / ...") while giving those children (illegal) idShorts. | Reference resolution accepts the index inside a SubmodelElementList regardless of any idShort present: the idShort is the AASd-120 violation, the reference is correct. |
| 11 | The official example's *leaf-type* list children (Reference/Property/File/Entity) carry no main semanticId of their own; its collection-type list children (Document, DocumentId, …) do carry one. | Inside a list scope, the sole child row also matches by element kind when the child has no *main* semanticId — even if it has a supplemental one (the example's language codes do). Keying the fallback on the full candidate set instead broke exactly those language children. |
| 12 | The template's own submodel `semanticId` is a `ModelReference` with a `Submodel` key, not an `ExternalReference`. | The expected reference type is read from the template, so an instance mirroring it (ModelReference) is conformant. An `ExternalReference` with the same key value identifies the same template and draws HDL3 (info), not a failure. An earlier version hardcoded `ExternalReference` as expected and so reported a false HDL3 against the official example. |
| 13 | ECMA-376 (OPC) resolves a relationship `Target` that does not begin with "/" against the *source part's* directory, not the package root. | Relationship targets are resolved that way (`X2`/`X4`); treating every target as root-relative rejected conformant packages that use relative targets. Absolute targets (leading "/") are unchanged. |
| 14 | An element may declare its identity through `supplementalSemanticId`s as well as its main `semanticId`. | Matching folds an element's supplementals into its candidate spellings, symmetrically with the template side. The in-list kind fallback still keys on the *main* semanticId being absent, so a child identified only by a supplemental is not mistaken for a mislabelled one. |
| 15 | §2.1: VDI 2770 requires PDF/A files. | HD-D10 checks for a DigitalFile of content type `application/pdf` per DocumentVersion, as a **warning**: a content type establishes PDF, not PDF/A conformance, and a non-PDF rendition (e.g. a CAD model) is a real-world case §2.1 flags but that this tool cannot call an error. |
| 16 | An element that declares its main identity as one row's semanticId *and* a sibling row's identifier as a `supplementalSemanticId` claims two rows' identities at once. | The walk assigns it to one row (first match wins), but the hand-rule navigation (`child_of`) matches on the union and may also read it for the other row, so such an element is **over-reported**. It is not hidden and no conformant or official-example element does this (real supplementals are same-identity CDP/`~N` spellings) — a mis-modelled element only. Left as a known limitation rather than risk a navigation refactor. |
| 17 | `xs:date`'s lexical space allows years outside `datetime.date`'s 1–9999 range; HD-D8 and TD-D1 check the value lexically to accept them (e.g. `-0001-01-01`). Three far-edge spellings used to diverge from aas-core3's reading and were recorded here rather than chased: a `0000` or leading-zero year was over-accepted, and a BCE leap year was judged in both directions. | Chased, because the ledger was the wrong place for them. Two of the three were **over-rejections** — `-0001-02-29` drew a MUST finding against a file aas-core3 calls conformant — and the metamodel channel is no backstop in that direction: it accepts what it accepts and says nothing. XSD 1.0 has no year zero and no leading zero past four digits, and `-0001` is 1 BCE, so the leap rule divides a year one greater. All three are read the way aas-core3 reads them now; `tests/test_values.py` compares the two readings over the whole corpus and names what is left (#31). |
| 18 | A `File` element's value and an OPC relationship `Target` are different kinds of string: a Target is a URI reference resolved against its source part (#13), while a File value is a part name, which ECMA-376 Part 2 defines as absolute, "/" separated, reserved characters percent-encoded, and free of empty, `.` or `..` segments. Files in the wild are not written that way. | One normaliser, two entry points. The spelling is normalised for both (the other separator, a leading `./`, a doubled separator, a step up and back, a percent escape); where the name starts from stays different. A literal match is tried before the normalised one, so an archive that really holds `%20` in an entry name keeps it — and relationship resolution lands on the entry the archive holds rather than on the normalised spelling, The two entry points ask in different orders -- the chain tries the literal first, the File rule the normalised first -- so on an archive holding two spellings of one name, or a value that is no part name at all, they can still land on different entries. Three cases were constructed and they do: a value of `../evil.step`, an archive holding both `files/x.step` and `/files/x.step`, and a target resolving to a part that is absent while the File rule's normalisation finds one that is present. Nothing published produces any of them, and closing it means one entry point rather than two, which is 0.1.2's. A target that is no part name at all is passed through unresolved rather than dropped: dropping it took X4's question away with it. Evidence for the strict reading: of the ten File elements in the official 02004 example, the seven that name a part all name it absolutely (two carry an empty value and one an external URL, neither of which is a part name); 02003's sample names three, also absolutely, and the official packager sidesteps escaping by substituting characters (`https___demo_com_ContactInformationAAS`) rather than encoding them. A value that climbs out of the package is not a part name at all, and HD-D7 says so as a distinct finding from a part being absent — the remedy is the same sentence, so it is the same rule. |

Thirty-six elements of the template are placeholders for content a manufacturer may add, all of which share one identifier, so six siblings in a single scope carry the same one. | No rule is generated from them, and the generator drops the subtree before it is numbered. Generating rules would demand the unconstrained; and with six siblings sharing an identifier, the first row would claim every arbitrary element the walk met and then fault it for being the wrong kind. A manufacturer's own properties pass without comment, which is what the sentence says. |

Those rows cannot be violated by count, so the suite proves them live by kind instead. |
